Späne & Eiche

Farbsystem — Schreinerei Web-App

Stand27.08.2026 · v1

Ein Farbsystem für eine App, die an zwei sehr verschiedenen Orten bedient wird: am Bildschirm im Büro und am iPad in der Werkstatt — mit Staub auf dem Glas, Gegenlicht vom Tor und oft nur einer freien Hand. Deshalb steht Orange nicht als Dekoration in diesem System, sondern als Signalfarbe: es zeigt, wo die nächste Handlung liegt. Alles andere hält sich zurück.

A · BASIS

Drei Familien

Orange führt, Eiche trägt, Petrol gleicht aus.

Die Neutrals sind bewusst kein kaltes Grau: sie tragen einen leichten Rotstich, damit sie neben dem Orange wie Holz wirken statt wie Beton. Petrol ist die Gegenfarbe — für Diagramme, ruhige Flächen und alles, was nicht um Aufmerksamkeit konkurrieren soll.

B · REGEL

Orange trägt keinen weissen Text

Die eine Entscheidung, die alles andere ordnet.

Weisser Text auf dem Marken-Orange erreicht nur 3,18:1 und fällt durch die Barrierefreiheits-Prüfung — auf einem iPad im Gegenlicht ist er schlicht nicht mehr zu lesen. Statt das Orange dafür abzudunkeln, bis es braun wird, dreht das System die Regel um: Orangefläche bekommt dunklen Text. Das ist dieselbe Logik wie auf jedem Warnschild und jedem Maschinenschalter — und es gibt der App einen eigenen Look statt des üblichen weissen Buttons.

Orange als Fläche

Nur für die eine Hauptaktion je Bildschirmbereich. Zwei orange Flächen nebeneinander heben sich gegenseitig auf.

Orange als Text

Nie die Markenstufe, sondern die dunklere Stufe 700 (hell) bzw. 400 (dunkel). Im Code: --brand-text.

Orange ist kein Status

Warnungen sind gelb-golden, Fehler rot. Wäre die Warnung orange, könnte niemand mehr Marke von Problem unterscheiden.

Orange gehört dem Fokus

Der Tastatur-Fokusring ist immer orange, 3 px, mit Abstand. In der Werkstatt wird viel getabbt statt getippt.

C · STATUS

Zustände lesen sich ohne Text

Vier Bedeutungen, klar getrennt vom Orange.

Jeder Status hat Farbe, Fläche und Rahmen — und zusätzlich einen Punkt als Form, damit auch bei Farbsehschwäche oder verstaubtem Display noch etwas zu erkennen ist. Farbe allein trägt nie eine Information.

E · SCHRIFT

Drei Schnitte, drei Aufgaben

Alle drei liegen bei Google Fonts.

Archivo — Überschriften und Panel-Titel

Eine technische Grotesk mit leicht kondensiertem Bau. Kräftig genug für Titel auf kleinen Flächen, ohne sich wie eine Werbeschrift zu benehmen. Nur in 600 und 700, nie für Fliesstext.

IBM Plex Sans — Fliesstext, Beschriftungen, Bedienelemente

Offene Formen, klar unterscheidbares I / l / 1 — wichtig bei Artikelnummern, die jemand vom iPad abliest. Mindestens 16 px, damit Safari beim Tippen nicht ungefragt hineinzoomt.

IBM Plex Mono — Masse, Nummern, Mengen

Alles, was in einer Spalte untereinander steht, läuft monospaced mit tabular-nums. So sind 712,0 und 1162,0 auf einen Blick vergleichbar, statt gegeneinander zu verrutschen.

F · CODE

So wird es benutzt

tokens.css einbinden, dann nur noch Tokens schreiben.

Komponenten greifen nie auf die Rohpalette zu, sondern immer auf die semantischen Tokens. Dadurch stimmt der Dunkelmodus automatisch — und ein späterer Farbwechsel ist eine Änderung an einer Stelle. 

/* richtig — Absicht statt Farbwert */
.auftrag-karte {
  background: var(--bg-surface);
  border: 1px solid var(--border-subtle);
  color: var(--text-base);
}
.auftrag-karte__aktion {
  background: var(--brand);
  color: var(--text-on-brand);   /* nie #fff */
  min-height: var(--touch-comfort);
}

/* falsch — bricht im Dunkelmodus und in der Sonne */
.auftrag-karte__aktion {
  background: #F26419;
  color: #FFFFFF;
}

Der Dunkelmodus deckt drei Fälle ab: Systemeinstellung hell, Systemeinstellung dunkel, und die ausdrückliche Wahl im App-Menü. Alle drei sind in tokens.css hinterlegt — mit dem Knopf oben rechts kannst du sie hier direkt vergleichen.
